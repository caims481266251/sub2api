# OpenAI 容器账号：保存 2FA 与 401 自动恢复

实现分支：codex/vm-kernel-account-mode。范围仅为 docker_kernel 的 OpenAI 标准 OAuth 账号；复用现有凭证运营、加密、任务 Worker、代理、账号调度及计费。普通账号沿用原处理流程，无新增数据库迁移。

## 使用入口

- 新增账号选择容器模式、2FA 登录，输入「邮箱----密码----2FA密钥」。登录结果先校验邮箱和稳定账号标识，再导入账号、加密保存登录信息和登记凭证运营。
- 中间保存失败时，账号保持不可调度；页面重试复用已完成登录结果。关闭页面后可重新导入，或到凭证运营补全保存。
- 账号管理的重新授权弹窗提供「使用已保存信息重新授权」和「复制 2FA 完整信息」。无需重新输入密码和密钥。
- 修改保存信息复用「凭证运营」入口。复制仅在管理员主动操作时读取完整信息，统一四横线格式，不在普通账号详情、状态返回或日志中输出秘密。
- 使用原有持久加密密钥和登录 Worker；已有容器账号须先保存完整信息。导出复用管理员权限及 no-store 响应。复制兼容已有浏览器剪贴板降级逻辑，临时数据在操作结束后释放。

## 请求与恢复链路

同步、SSE、WS，以及 /v1/chat/completions 转换后的请求，经过相同结果观察入口：

1. 内核明确返回上游 401：直接登记 2FA 登录任务，不先尝试 refresh，不自动重放原业务请求。
2. 按真正出站凭据快照与数据库当前值比较；迟到的旧 401 不暂停新凭据。
3. 锁定账号行，在同一事务中标记认证暂停并插入任务、调度 outbox。并发 401 合并成一个任务。
4. 现有 Worker 使用已保存信息及登录出口执行。领取时检查身份及凭据版本；回调沿用身份校验、凭据 CAS 和任务所有权检查。
5. 成功仅解除本流程造成的认证错误；保留手动禁用、schedulable、并发、额度、限流和代理暂停。协调器继续观察容器健康，恢复后按既有机制更新凭据投影。
6. 同一凭据的失败自动任务不循环登录，手动可以重试。其他任务占用账号时保留认证暂停，由凭证运营巡检在槽位释放后重新检查；失败历史仍然去重。

管理端、内核内部接口的 401，以及代理错误、429、5xx 不走这个自动登录分支。凭证运营探测到容器上游 401 使用同一持久去重路径，不能通过手动任务入口绕过去重。

保存信息缺失时，无法完成自动 2FA，仍交由原有认证错误处理。不能把「容器健康」「授权成功」「业务请求成功」视为同一个状态。恢复成功后，业务调度还要满足原有准入规则。
