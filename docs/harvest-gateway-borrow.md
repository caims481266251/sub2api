# 网关借票

> 历史实现记录：本文描述旧版门票采集与复用流程，仅供版本追溯，不作为当前部署或配置指南。新人请从[新人入门](新人入门.md)开始；协议配置和账号质量检测分别参阅 [Excel / BPS](excel-bps.md) 与[质量运维](account-quality-operations.md)。不要按本文启用旧开关或部署配套服务。

入口：智能运维 → 打票流程（`/admin/harvest-flow`）→ 网关借票。默认关闭，卡片默认折叠。来源与目标必须分开选择；保存启用后自动获取路由并验证目标。Cookie 与临时探针门票只留在内存，不返回管理接口、不写历史表。

来源使用轻量请求取得路由 Cookie。可在「来源借票模型」中为每个所选来源账号单独选择或输入文本模型 ID，默认 `gpt-6-astra`，旧配置继续使用默认模型。配置字段为 `cookie_pool.source_account_models`（账号 ID → 模型 ID）；沿用来源账号已有模型映射，响应必须完整成功且模型与实际请求一致才能收集 Cookie。普通来源业务请求不收集 Cookie。更换来源模型并保存后会清空旧路由验证状态并重新准备；非 Astra 模型取得的 Cookie 仍须通过目标的 Astra 探针，不能保证跨模型借用成功。

目标复用现有 `openai_codex_state_probe.go` 两轮 Astra 探针，在借来的 Cookie 与同一出口上使用目标自己的凭据：两次请求都完整成功，续接没有新门票（或回原票）才可用；新门票、缺票、请求/流失败、路由变化均不可用。探针结果是本次门票状态，不代表永久模型能力。手动验证会重新探测，不复用旧的通过状态。

已验证且未过期的路由允许目标业务请求并发复用。复用要求 Cookie、目标凭据、出口和请求身份与验证时一致；新的目标验证和来源恢复仍串行执行，身份不匹配的请求不能绕过验证。

目标复验的打票和续接阶段分别最多尝试 3 次（首次加 2 次重试），间隔 500 毫秒、1 秒。网络异常、单次超时、HTTP 408/429/5xx、响应流失败以及打票未返回门票时，先重试当前阶段；保持目标凭据、借用路由和出口，续接重试保留第一轮成功取得的目标门票。完整续接返回新门票、路由变化、认证拒绝或其他不可重试状态不重试。所有重试仍受单个候选 90 秒、整个恢复 180 秒和请求取消约束；耗尽后交给原有候选切换、来源补领逻辑。此机制只用于目标门票复验，不重放业务生成请求。服务日志 `astra_target_probe_retry` 记录重试阶段、次数和失败分类，不记录 Cookie 或门票。

未开启节点轮换时，来源获取最多 4 个账号并发执行，保留所有成功候选，不因首个来源成功而停止其他来源。目标按候选顺序验证，返回新门票或其他探针失败时淘汰该候选，切换其他来源。当前批次连续 3 个候选失败（或候选提前耗尽）后自动重新调用来源获取新 Cookie，再由目标打新门票并续接验证；每次恢复最多 3 批候选、每批最多验证 3 个候选，恢复阶段总计 180 秒。普通获取跳过尚在避让期的失败来源；自动补领允许该来源重新获取，但原 Cookie 在其有效期内仍被拒绝，不能因重新获取而恢复。补领和复验与手动验证、保存后的自动准备、HTTP/WS 借用共用恢复逻辑；多个请求不会同时启动重复恢复。页面显示「目标验证失败，正在重新获取路由 Cookie」。尝试耗尽、来源不可用、配置变化或取消时停止，继续拒绝未验证业务请求。

## 无感借票（单实例、固定出口）

`cookie_pool.seamless` 默认关闭。开启后服务启动和保存配置都会进入后台维护；每 5 秒检查库存，不依赖页面轮询或业务流量。支持固定目标出口及来源代理亲和，不能与托管节点轮换同时开启。多实例共享/接管不在本版本支持范围内。

候选使用独立 Cookie/出口指纹保存，最多 32 条；每个目标最多保留 4 种请求身份，每种身份最多 2 条已验证路由，分别作为主用和备用。身份包含目标凭据、账号头、代理、客户端身份头、门票头、请求路径及 TLS profile。后台从数据库刷新目标身份，并维护已观察到且近期使用的业务身份。新身份未通过验证不能使用其他身份的缓存；凭据或规范出口变化取消旧任务并清理相关通过记录。探针门票不作为业务共享门票使用。

后台每个目标串行、全局最多 2 项补充任务；来源每批最多 2 个账号，按配置顺序轮转，不一次排队全部来源。缺备用或最年轻的有效路由进入预热窗口时补充；默认 230 秒 TTL 对应提前 150 秒，较短 TTL 使用其 2/3。两条均够新时停止补充。重复 Cookie 不增加库存、不延长原到期时间，上游缩短有效期会同时约束既有通过记录。Cookie 指纹期限记录最多 512 条，到期后保留 10 分钟用于去重。

新请求只选剩余有效期超过 15 秒、身份匹配的已验证路由；主用进入安全余量时自动使用备用。在途请求持有稳定 Cookie 快照，切换不重放请求、不截断流。完全缺票时业务最多等待 5 秒，客户端取消不会取消后台任务。后台每轮最多 180 秒、最多获取 3 批来源并验证 6 个候选；目标阶段重试仍受该预算和候选到期时间约束。失败后按约 5/10/20/30 秒退避。手动验证必须产生新的通过证据，不能把原主用状态直接当作本次成功。

滑动 60 秒预算计入每次真实发送（包含重试）：全局最多 60 次，来源合计 12 次、每来源 4 次、每目标探针 24 次。业务生成不计入探针预算。429 遵守 Retry-After；无有效值时冷却 30 秒。一个目标的候选失败不会清除其他目标的通过记录。备用失败保留有效主用；业务响应明确改变路由或拒绝身份时，会撤销匹配的通过记录。

状态接口的目标行新增 `routes`（主备、来源、网关、验证时间、到期时间）和 `maintenance`（阶段、是否运行、最近原因、失败分类、两阶段 HTTP 状态、重试次数、下次检查时间）。可用性和后台补充状态分别展示；账号调度读取同一规范目标身份的有效主备库存。Cookie、凭据、请求身份内容和探针门票仍仅保存在进程内。

支持来源代理亲和、托管 Mihomo 节点轮换及失败冷却。Astra 使用独立回环端口 17925–17932，与普通打票和 BPS 隔离。路由有效期不因重复使用延长；过期后重新获取和验证。无可用路由时拒绝目标借用，不自动退回未验证出口。

可选 WS 固定会话按 API Key、分组、账号和客户端会话隔离；后续请求必须提供响应 ID 并继续使用原连接。借票不复制来源账号的凭据或门票，也不替代普通打票的账号范围和门票策略。

可选号池调度在目标探针通过且路由有效时恢复本功能拥有的变更；否则按设置暂停账号、屏蔽 Astra 模型或移出指定分组。只修改所选目标，切换模式先恢复旧动作，遇到人工编辑冲突不覆盖。关闭接管保留当时状态。仅切换调度设置不清空已验证路由。

新增 `astra_gateway_history` 和 `astra_scheduling_states` 两张表；保留原私有版本迁移文件名和内容，已有实例可兼容。历史通过不代表当前可用。启用后会发送来源获取和目标探针请求；页面读取状态不触发请求。
