# GPT HTTP 会话归属与缓存路由

HTTP 文本请求先尝试已有的健康会话归属，再应用借票优先策略。目标是减少同一会话在普通兜底与借票之间的不必要切换，使已有的出站 session 和上游缓存身份得到复用。

## 行为

| 场景 | 调度 | 归属更新 |
| --- | --- | --- |
| 新会话 | 沿用借票优先和普通兜底 | 成功后确认 |
| 归属帐号健康且有容量 | 优先原归属，仍检查分组、模型、费用、权限、路由与并发 | 成功后续期 |
| 并发或本地 RPM 暂满 | 可由其他可用帐号执行；不增加亲和专用等待时间 | 临时分流不覆盖、不续期原归属 |
| 借票无合格路由或帐号失效 | 沿用原有同组重选及安全恢复流程 | 新帐号成功后接管 |
| 普通帐号已接管，借票恢复 | 活跃会话继续使用普通帐号；新会话仍优先借票 | 不自动切回 |
| 失败、取消、断流或仅有响应头 | 不认定为成功接管 | 不确认归属 |
| 所有帐号忙 | 保留原调度的等待策略 | 不创造额外业务并发 |

成功接管不代表缓存已经命中；上游仍决定缓存是否命中及保留多久。普通帐号接管的活跃会话会继续消耗普通通道容量，应同时观察普通帐号负载、费用和失败率。

## 范围与安全边界

- 接入 OpenAI 平台的 HTTP Responses、Chat Completions 和 Messages 文本入口。
- 原生 `previous_response_id`、借票 HTTP 响应续接、Guardian 父会话约束、远程压缩和 Responses 图片意图保留已有专门处理。WebSocket、搜索、独立媒体和其他平台不应用这项新策略。
- 不改变消息、工具调用与 `call_id`、推理历史、缓存键、出站 session 的构造，也不新增重试或额外上游发送。
- 响应归属、历史恢复及帐号绑定状态继续使用已有校验；缓存亲和从不提供跨帐号重放权限。
- 显式 session 优先；无显式 session 时沿用原有内容摘要作为弱亲和。弱亲和不能证明两次请求拥有相同上下文或同一响应。
- Guardian 的父帐号提示在成功确认后写入 API Key 与分组隔离的辅助键；该提示允许子任务使用不同模型，仍是软偏好，不是响应所有权。

## 配置与灰度

```yaml
gateway:
  openai_session_affinity_enabled: true
  openai_session_affinity_group_ids: []
```

默认开启；空分组列表适用于所有分组，`[2]` 仅开启分组 2，`0` 表示无分组。配置沿用服务现有加载方式，修改配置后需由部署流程重启使其生效。环境变量 `GATEWAY_OPENAI_SESSION_AFFINITY_ENABLED=false` 可关闭策略。

正式归属有效期沿用 `gateway.openai_ws.sticky_session_ttl_seconds`，未配置时为 1 小时。这个参数表示本地调度绑定有效期，不保证上游缓存保留时长。

关闭开关后恢复原选号策略，不删除响应归属、历史或新亲和记录。重新开启后，未过期的归属仍会经过当次准入检查。

新记录采用独立命名空间，不把无法确认租户/模型作用域的旧 Sticky 绑定直接提升为新归属。首次启用时已有会话可能发生一次重新选择；后续按新记录保持。

## 原子状态

`openai_session_affinity:v1:{digest}:owner` 和 `:pending` 使用相同 Redis Cluster 哈希槽。digest 隔离用户、API Key、分组、请求模型及逻辑会话摘要。记录仅包含帐号、通道、随机版本号和待确认状态，不保存提示词或凭据。

首次取得容量时，通过 Lua 原子创建待确认归属，最长 5 分钟。并发首请求尽量收敛到同一个候选；竞争失败者先释放已取得的帐号槽位，最多再尝试一次该候选。候选满载时仍可临时分流，不把会话强制串行化。

等待槽位后才发现另一个请求已确定归属时，本次只做临时分流。待确认记录不会续期；失败残留自动过期。

只有转发成功、未取消、未断连且结果完整时，才通过版本比较确认或接管正式归属。原帐号失效后的兜底执行不提前覆盖正式归属。旧请求晚完成、已过期记录和并发失败者不能把新的归属改回去。

缓存访问失败时保留原有可用帐号调度，不写入可能覆盖其他实例的归属，不回读作用域不明确的旧绑定。每次新亲和存储操作使用有界请求上下文。

## 观测

业务调用的“请求耗时详情”新增“会话归属与缓存路由”，旧记录没有该信息时不显示。后端时间线 JSON 增加可选的 `session_affinity`：

- `decision`：`new_session`、`owner_hit`、`temporary_spillover`、`takeover`。
- `reason`：原归属可用、并发/RPM 满、原归属不可用、费用准入、并发归属竞争等。
- `owner_account_id` / `execution_account_id`：原归属或待确认候选与本次执行帐号。
- `owner_pending`、`success`、`owner_committed`、`cache_unavailable`：候选状态、业务终态、归属更新结果和存储故障。

`takeover` 表示尝试接管，必须结合 `owner_committed=true` 才表示更新成功。`owner_hit` 后成功续期同样会返回 `owner_committed=true`。

结构化日志事件 `openai.session_affinity` 包含上述信息、`trace_id`、隔离后的会话摘要、模型、缓存 token 与首 token 时间。日志中的 `total_input_tokens` 已包含缓存读取和写入，不能重复相加；数据库用量的 `input_tokens` 则是扣除缓存后的互斥桶。

灰度对比应按会话、模型、推理等级与输入长度分组，同时观察：

1. 普通→借票的无必要回切次数和同帐号连续请求比例。
2. 按输入 token 加权的缓存命中率及每请求分布。
3. 临时分流、正式接管、存储失败和版本冲突比例。
4. 普通帐号负载、费用、最终错误率、首语义和首次可见内容 P95。

本功能不承诺固定缓存命中率，也不把上游隐藏推理或排队导致的慢首字判为可安全重放的错误。
