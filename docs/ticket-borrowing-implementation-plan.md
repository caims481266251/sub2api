**独立借票页面与目标严格路由准入：实现计划**

日期：2026-10-10。状态：独立管理、PostgreSQL 权威准入、后台协调与 HTTP 业务闭环已实现，已通过针对性回归并部署至本地 18080 服务。真实来源迁移与目标启用保持显式操作。审查记录见第 12 节；实际实现与操作说明见 `docs/ticket-borrowing.md`。

**1. 已确认的产品目标**

新增“智能运维 → 借票管理”独立页面，建议地址 `/admin/ticket-borrowing`。来源账号在此页导入、维护和参与借票；使用独立数据表和独立调度，不进入普通账号列表、普通分组及业务账号选择。来源模型可单独设置，默认采用已有成功样本的 `gpt-6-luna`。

目标保留在普通账号管理中，编辑弹窗仅增加“启用借票”开关及只读路由状态；账号列表显示同一状态，便于直接判断能否接单。借票页面可只读汇总已启用目标，并提供刷新路由、查看记录等运行操作，目标启用配置只保留一个写入入口。

目标开启后，没有当前有效且对该目标验证通过的网关路由，就禁止向该账号发送业务请求，后台继续寻找。取得新有效路由后自动恢复准入。按用户要求采用账号级约束；第一版验证对象仍以当前 OpenAI OAuth、Astra Responses 链路为核心，其他模型或传输必须有相应有效性证据才能放行，不能把 Astra 的通过状态当作所有模型的通行证。

普通账号原有禁用、分组、模型权限、额度、冷却及并发限制仍参与最终判断：路由有效只是新增的必要条件。借票状态独立计算，不反复覆盖管理员维护的 `schedulable` 或账号主状态。

2026-10-10 用户补充：有效路由只要未过期，就允许目标正常参与调度。取消提前 15 秒停止使用的设计；后台补票、候选验证失败、来源冷却或取票预算耗尽都不影响现有有效路由的业务调度。

**3. 数据与职责划分**

| 对象 | 保存内容 | 存储与边界 |
|---|---|---|
| 借票来源 | 名称、独立 ID、凭据、凭据版本、取票模型、启用状态、代理策略、指纹配置、冷却原因 | 新表 `ticket_borrow_sources`；无普通账号和分组外键；凭据复用现有加密组件 |
| 目标开关 | `borrow_enabled`、策略版本 | 独立 `ticket_borrow_targets` 表关联普通账号；专用接口原子更新，实际发送绕开调度缓存读取主库 |
| 借票策略 | 后台是否运行、来源并发、目标验证预算、候选有效期上限、退避、出口/指纹轮换策略 | 独立版本化配置；不再依赖旧 CookiePool 的全局开关才能执行准入 |
| 路由候选 | Cookie、首次观察时间、绝对截止时间、host、来源 ID、来源身份和出口版本 | 运行时对象，按完整 Cookie 与环境去重；只有候选身份，不能用于业务 |
| 目标路由绑定 | 目标 ID、目标身份版本、候选 ID、模型/传输范围、验证时间、截止时间、状态版本 | 运行时已验证绑定；不是全局“host 可用”标签 |
| 借票事件 | 阶段、耗时、失败类别、来源/目标 ID、脱敏指纹、关联任务及路线版本 | 独立事件表；分页、保留期和清理机制；不保存原始票据或密码 |

来源凭据刷新单独执行，复用 OAuth 协议和加密原语，不复用会写普通账号数据的整套 worker。刷新用版本条件更新，避免旧请求覆盖新凭据。来源与普通目标使用不同资源命名空间，覆盖连接池、锁、限流、缓存和日志，不能只用裸整数 ID 区分。支持批量导入、批量启停、修改模型/代理、重新授权及删除。停用或删除来源停止新采集及该来源的待处理任务，删除时清理来源凭据；已发布的目标绑定拥有独立路由快照，不因来源记录的管理操作而提前失效，继续使用至截止时间或确认失效。独立快照不含来源 OAuth/刷新令牌；其必要路由材料按 TTL 清理，历史只保留脱敏来源引用。

路由绑定键由目标主体 ID、目标身份版本、Cookie 指纹、有效出口版本、TLS/UA/设备配置和适用模型/传输构成；会话 ID、conversation ID、previous_response_id 和具体 turn-state 不进入账号级路由可用键。会话门票及续接关系独立保存，并关联 binding_id。身份版本、访问令牌版本、候选版本、后台设置版本各自独立，不以一个全局 revision 使所有路由同时失效。令牌刷新采用新旧版本衔接：新凭据需要复验时在后台验证，原凭据仍合法且路由有效时继续服务；原凭据确实失效或主体发生变化才阻断旧上下文。

使用 PostgreSQL 主库统一保存目标策略、任务租约、版本、撤销状态和加密路由材料，避免数据库与 Redis 双写窗口。发布结果必须携带任务租约代次和策略/身份版本，使用原子条件更新，过期 worker 不能把旧结果重新置为可用。调度列表可使用提示缓存，实际发送前必须检查权威状态。PostgreSQL/解密/版本读取失败按不可用处理。

应用进程重启本身不撤销有效绑定。只要共享权威状态仍完整、密钥可用、身份和版本匹配且未过期，重启后或新实例加入时可以恢复使用，不以 worker 代次变化当作路由失效。PostgreSQL 权威状态丢失、回滚到旧备份或绑定上下文不完整时才进入待复验；数据库历史中的“曾经通过”不可直接恢复为可用。worker 租约代次只限制后续结果发布，不决定已发布绑定的有效期。

**4. 状态与准入规则**

把“是否允许调用”和“后台正在做什么”分开，避免正在补票时把仍有效的主路由显示为不可用。

| 目标展示状态 | 允许业务调用 | 后台行为 |
|---|---|---|
| 未启用 | 按普通账号原有规则 | 不为该目标借票 |
| 等待有效路由 | 否 | 排队寻找候选 |
| 获取中 / 验证中 | 没有现存有效绑定时否 | 执行来源获取、目标验证 |
| 路由可用 | 在其他账号条件也满足时是 | 必要时预取替代候选 |
| 路由可用 · 正在补票 | 是，直到现绑定失效 | 后台验证替代候选 |
| 冷却中 | 无有效绑定时否 | 按限流/退避时刻恢复 |
| 路由失效 | 否 | 撤销绑定并启动补票 |
| 目标有效上下文异常 | 否 | 等待修复，展示具体原因；仅来源或后台配置异常不覆盖现有可用状态 |

有效绑定必须同时满足：目标身份和影响路由有效性的策略版本匹配、请求模型与传输在验证范围内、目标验证通过、Cookie 和绑定未到期、绑定未被撤销，且目标普通调度条件满足。有效期判断严格使用 `now < expires_at`，不扣除发送安全余量，不要求剩余时间覆盖预计响应耗时。调度时有效但排队后到期的请求，在真正发送前重新选择有效绑定或拒绝。后台可以依据预计探针耗时跳过来不及验证的新候选，此规则不得用于清理已经验证通过的有效绑定。

Cookie 截止时间取上游期限与本地候选 TTL 上限的较早值。无上游明确期限时使用本地保守上限。重复拿到相同 Cookie 不重新起算有效期；提高配置上限不延长已入池候选。沿用现有 230 秒上限作为初始默认，明确它是本地策略值，不是上游保证。页面倒计时、准入判断和运行时清理统一使用同一个截止时间，不额外提前停止调度。提前补票阈值仅用于启动后台获取，不缩短当前路由的可用期限。

共享截止时间与准入使用同一 PostgreSQL 权威时钟（clock_timestamp），本机单调时钟用于耗时和超时。数据库定期清理仅用于回收数据，不能单凭路由记录存在判断未过期。前端接收 server_now、expires_at 和后端资格结果，剩余不足 1 秒显示“<1 秒”，不因秒数取整为 0 显示不可用。事件明细写入失败不撤销绑定，权威状态无法确认则暂停新准入并展示原因。

后台“暂停获取”只暂停 worker，既有绑定在自然期限内可用，过期即禁止；后台异常、关闭旧 CookiePool 或没有来源也不会让已启用目标直接调用。只有目标账号自身关闭借票开关，才恢复普通准入规则。

后台取票冷却与业务账号自身的限流/冷却分别维护：前者不阻止有有效路由的账号调度，后者仍按普通账号规则执行。补票并发、重试预算、扫描顺序和后台暂停等策略修改不撤销既有绑定。已准入并发送的业务，不因执行过程中达到路由截止时间而主动中断；到期后阻止新请求和 WS 新 turn，后续是否完成以上游实际响应为准。

**5. 请求入口与并发边界**

采用两层检查：调度时排除不满足条件的目标；实际发送前以最新状态原子取得路由使用凭证，并绑定明确的路线版本。最终校验与取得凭证的时刻是准入边界，此前撤销的路线不得再获得新的使用凭证，此后已准入请求按在途请求处理。目标开关和身份版本修改必须在保存返回成功前完成权威准入状态同步，不能仅等待异步调度缓存刷新；跨存储更新失败时保留阻断标记并可重试协调，防止旧缓存继续放行。

最终准入调用不能包在缓存中的 `if borrow_enabled` 条件内：旧账号快照仍显示关闭时，也必须经过权威策略检查。实现采用单一 PostgreSQL 权威：成功查询且无策略行表示从未启用；查询失败必须拒绝。目标开关与版本在一个事务中提交，行锁与条件版本更新防止旧保存覆盖新状态，无需跨存储转换屏障。普通账号的其他入口（批量编辑、导入、自动配置、删除恢复）均遵守此更新路径，省略该字段的旧客户端不能覆盖开关。

普通并发槽位、连接池等待及正常凭据准备应在最终准入前完成；若最终准入后仍发生建连等待、重试或其他异步排队，实际写出 HTTP 请求或 WS turn 前重新检查期限/版本。使用凭证限定本次发送且不延长路线有效期。任意业务重试都是新的发送，必须重新准入，不持有旧凭证绕过到期检查。

需要覆盖普通负载均衡、旧调度器、粘性会话、previous_response_id、父/影子账号、显式目标请求、账号业务测试、重试和故障转移路径。影子账号按有效凭据所属目标继承限制，不能绕过父账号保护。纯取票/复验只允许内部可信工作类型绕过业务准入，不能接受客户端 Header 或 body 里的绕过标志。

HTTP 每次发送前检查；WS 首次建连、连接池复用和每次新业务 turn 都检查。连接池键绑定路线版本，旧路线失效后不能承接新 turn；允许已开始的响应按既有错误处理完成或终止。HTTP/WS 回退也必须经过同一准入服务，未完成接入的传输对启用目标明确拒绝。

WS 自动预热、HTTP→WS 桥接及内部辅助生成只要会向目标发送模型请求，同样受保护；普通业务不能通过标记为预热逃逸。现有 `checkBeforeWrite` 与实际 `WriteJSON` 之间还可能等待 RPM，因此最终绑定复核要放在该等待之后。只有专用借票 worker 创建的内部探针上下文可在无有效绑定时请求目标。

普通请求可按已有权限与会话迁移规则选择其他合格账号，但不可把当前无路由目标作为直连回退。显式指定目标或不能迁移的会话直接返回可识别错误。建议使用 HTTP 503、错误码 `borrow_route_unavailable`，并提供脱敏原因；只在明确已知冷却时提供可信的 Retry-After，不承诺一个未知恢复时间。

业务请求不在入口等待完整的 50 来源扫描；后台承担寻找任务。并发业务共享已验证路线的只读材料，但各自保持正确的目标会话上下文。不得把来源 OAuth、来源 turn-state 或一个探针的会话票据无条件注入其他用户对话。

路由换代不允许静默跨 host/出口搬迁不兼容的续接会话：能在原上下文合法续接则继续，否则返回明确的会话路由失效错误，不能复制票据强行恢复。

替代路由通过后可以成为新会话首选，但旧绑定在未过期且仍有效时继续保留。已绑定旧路线的会话和 WS 连接仍可正常发起新 turn，只有其自身绑定到期或确认失效才停止使用；主路由指针变化不等于旧绑定撤销。连接池淘汰需等待旧绑定到期/撤销和在途请求完成，不能为实现“原子切换”而清空全部连接。

**6. 自动借票流程**

1. 目标开启借票后立即登记为待获取；账号保存成功即生效，任务稍后执行，不因任务启动延迟留下放行窗口。
2. 每个目标只有一个有效协调任务；来源获取默认 3 并发，同一来源同时只允许一个获取任务；目标验证默认串行，避免同目标探针互相干扰。另设全局和单账号请求预算。
3. 以公平游标扫描全部启用来源，优先近期有表现的候选但保留其他来源机会。每个批次有边界，预算耗尽后保存游标继续，避免每轮总从第一个来源开始。
4. 来源使用自己的模型、凭据、代理和完整身份取得 Cookie。按候选内容及验证环境去重，同一失败候选在同一目标身份版本下不立即重试；新身份或新时间块可复验，失败 host 不永久拉黑。
5. 用目标自己的凭据执行两阶段验证。完整请求、明确目标门票、合法 Cookie、续接未出现不同门票以及无路由替换等必要条件都满足才发布绑定。流不完整、超时和网络失败记为无法判定，不发布可用状态。
6. 短暂网络/5xx/流错误可在有效期和预算内重试，建议每阶段最多额外 2 次并带抖动；429 遵守 Retry-After；401/403 进入凭据/权限故障处理。完整返回不同门票时切换候选，不把它无限重试成成功。
7. 第一条有效绑定即可恢复准入；候选获取结果不得覆盖已发布主绑定。接近本地截止时间时可获取一个替代绑定，原绑定仍有效则继续服务；新绑定验证通过后原子更新新会话首选，旧会话绑定继续保留至自身失效。
8. 可用绑定耗尽或被撤销后立即关闭准入并恢复搜索。持续失败使用有界退避和明确原因，不进行没有预算的永久紧密循环。

生产模式的目标是尽快取得可用绑定，取得后不强制跑满 50 个来源。另提供诊断模式“完整扫描全部来源”，用于未来回归，必须与生产任务互斥，且记录各来源已尝试/失败/跳过原因。

后台探针使用独立的获取/验证预算，业务调度及账号并发优先。探针不能长期占满目标业务并发槽；无法取得不影响业务的探针容量时延后验证。后台本地预算耗尽只暂停后台；上游明确返回的账号级限流仍按普通账号规则处理。诊断任务也不能通过锁住全部业务请求来制造“正常调度”状态。

**7. 出口、指纹与响应观察**

来源支持代理池及每账号独立指纹，轮换发生在新获取轮次或明确失败后，轮次内部保持一致。目标的一组验证和后续业务必须使用相同受控身份/出口版本。自动补票不得修改仍在服务的目标身份；默认在当前目标身份下探索新的来源候选。如需自动探索另一目标身份，需作为独立待验证上下文，原绑定保持可用，通过后只用于新会话；管理员明确替换/撤销当前目标身份则使不匹配的旧绑定失效。不能只在探针里使用临时随机指纹。

语言、时区按出口信息合理配置，TLS/UA/设备标识需一致。代理 SID 不能作为物理 IP 恒定的保证，外部 IP 查询只是辅助信息。无法确认预检结果不直接判死上游候选，最终以上游真实验证为准。

轮换功能作为可配置候选探索策略，不作为已经证实提高成功率的必开规则。按来源、host、Cookie、身份版本、出口版本分别统计，避免把“换了代理”与“换了 Cookie/时段”混为同一个因素。

业务侧补充现有 `observeBusiness`：当实际发送了既有目标 turn-state，而响应返回不同 turn-state，按当前判据撤销对应目标绑定；没有携带旧票的首发正常签票不算异常。Cookie 改变/删除/过期、身份错误也触发相应撤销。更新必须比较路线版本，旧请求失败不能误删已切换的新绑定。

失败作用域必须明确：来源获取失败只影响来源；新候选验证失败只淘汰该候选与目标身份组合；有效绑定的真实业务或明确复验失败仅撤销该 binding_id；其他独立有效绑定仍可调度。网络超时、单次 5xx、日志错误及不明确的代理 403 不能直接当作路由失效。只有已确认目标凭据/主体异常等账号级证据才扩大为整个目标阻断，暂态错误仍执行普通账号既有保护规则。

可在响应头阶段确认不合格时，停止将其作为成功业务响应转发；已经开始下发的流无法撤回，记录失败并阻止后续新请求，不自动重放业务以免重复工具调用或计费。并发其他请求已经获得准入的，按在途规则处理，不能承诺单个失败能撤回全部已发送请求。

**8. 页面与 API**

借票页分为来源列表、目标运行概览、策略设置、事件记录四个视图。来源列表显示模型、凭据状态、出口/指纹配置摘要、最近获取结果和冷却；目标概览显示是否允许调用、当前 host、剩余期限、上次验证、后台阶段及最后失败原因。记录区分别统计获取成功率、目标验证通过率、业务完成率、业务票据保持率；诊断题正确率独立展示。

建议接口前缀 `/admin/ticket-borrowing`：

- `sources`：增删改查、批量导入/启停、重新授权和代理配置。
- `settings`：版本化策略读写，含后台暂停/恢复。
- `targets`：已启用目标的只读状态与刷新路由操作。
- `events`：分页查询取票、验证、撤销、冷却记录。
- `diagnostics`：创建/取消有界诊断任务；状态查询不重复触发上游请求。

目标开关展示在普通账号编辑中，通过 `/admin/accounts/:id/ticket-borrowing` 专用接口即时保存，避免旧客户端覆盖。所有 DTO 去除原始 Cookie、turn-state、访问令牌、代理密码；页面只显示脱敏身份摘要。新来源凭据必须纳入现有加密密钥丢失检测、备份恢复及数据清理范围。

现有 `credential_encryptor.go` 的已存密文检测只查询重登配置表，实现时必须增加独立来源表检测，避免密钥丢失后误认为没有密文而生成新密钥。多个实例共享加密路由时需使用一致的受管密钥与 key_id；各实例独立生成本地文件密钥不能直接互通。首次启用迁移需初始化普通账号的权威开关状态并验证密钥可用，避免正常未启用账号因未初始化状态被误阻断。

**10. 迁移与回滚**

旧配置只有普通来源账号 ID，不能静默把所有普通账号复制或搬走。提供迁移预览：展示选中的旧来源、来源模型和代理，检测与普通目标身份冲突，以及普通业务用途。只有显式选择“转为借票专用”的账号才迁移凭据所有权；同一身份不能由两个独立 worker 同时刷新同一刷新令牌。

执行迁移时停止对应旧来源/目标的旧借票任务，在事务中建立独立来源记录并保存迁移映射；转为专用的原记录退出普通调度并归档，保留历史引用。单纯设置 `schedulable=false` 不会停止现有 OAuth 刷新：必须记录凭据维护所有权，旧刷新、自动重登、管理探针和其他凭据写入任务一并排除已迁移主体。先阻止新旧 worker 取得双重所有权，等待旧在途刷新结束，再复制最新凭据并切换版本；迟到写入需条件更新拒绝。若账号还用于普通业务，则不自动迁移，通过独立来源导入流程解决用途冲突。新导入也要检查与普通账号及独立来源库的主体重复，不能以换名字绕过同一刷新令牌的所有权约束。迁移要可重入、可预览、可追踪，不删除原有使用历史。

新目标由普通账号开关唯一管理。旧借票面板在切换后改为新页面入口/迁移提示；旧来源池、旧目标列表不能继续并行影响新目标。现有打票流程中与新借票无关的功能保留各自职责。

回滚必须先停止新任务并使已启用目标处于禁止调用状态；不能直接退回一个完全忽略 `borrow_enabled` 的旧二进制。可选择回退到保留准入检查的兼容版本，或经明确配置操作关闭目标借票/暂停目标后再回退。原始业务账号开关和分组快照仅用于有条件恢复，不覆盖迁移后管理员的新修改。

**11. 验收清单**

- 来源独立：新增、刷新、删改来源不会创建普通账号或改变普通分组；同 ID 命名空间无碰撞；凭据不泄露。
- 严格准入：未取票、候选未验证、验证异常、过期、撤销、全局暂停后过期、共享状态丢失等待复验等导致没有任何有效绑定时，启用目标的业务上游发送次数为零；无法读取权威准入状态时也必须拒绝。单纯进程重启且权威状态完整时恢复现有有效绑定。
- 其他约束：已有可用路线也不能越过目标禁用、额度、模型、分组、并发及影子账号的限制。
- 并发正确性：50 个同时入站请求只触发一个目标准备任务；路线轮换原子发布；旧失败/旧 worker 无法覆盖新结果。
- 有效期：重复 Cookie 不续命；距离截止时间 15 秒、1 秒及不足 1 秒时，只要仍有效且其他普通调度条件满足就允许发送；恰好到期及到期后拒绝新请求；排队跨越期限时发送前拦截；已经发送的请求不因期限到达而主动中断。改变代理/指纹/有效凭据身份等影响验证上下文的配置使旧绑定失效，调整后台补票策略不影响现有有效绑定。
- 补票隔离：后台验证新候选失败、获取冷却、暂停、预算耗尽时，现有有效绑定继续正常调度，不因补票阶段降权或暂停。
- 有效绑定保留：来源停用/删除、后台设置修改、新路由成为首选、后台任务租约换代、应用正常重启均不提前撤销仍有效的绑定；旧 WS/会话在旧绑定有效期内仍可调度。
- 身份与所有权：并发多个独立会话不会产生账号级身份冲突或每会话重复取票；迁移时旧刷新任务无法覆盖新凭据；双库重复主体不能产生双重维护。
- 策略一致性：用“缓存仍显示借票关闭”的旧账号快照发请求，启用成功后仍受最终准入拦截；开关切换各崩溃点、数据库/Redis部分失败、修复任务乱序和旧客户端更新均不放开已启用目标。
- 协议覆盖：粘性、previous_response、直接目标、HTTP、WS 新连接/复用/新 turn、传输回退均执行检查；无法迁移的会话明确失败。
- 重试分类：暂态错误有界重试；新门票切换候选；429 冷却；业务已发送后不自动重放。
- 事件准确：候选获取、目标通过、业务完成、业务门票变化分别计数；重复查询状态不增加成功次数。
- 前端：普通账号编辑只需开关和状态；无路由明确显示禁止调用原因；借票页完成来源批量维护；中英文及移动端可用。

测试先采用可控制上游和时钟的 service/repository/integration 用例，重点验证拒绝时“零上游业务请求”和竞争条件；前端运行相关组件测试、类型检查与构建。真实验收使用已有来源和目标配置，先获取通过路线，每次通过后立即请求一次糖果题并记录实际发送环境及门票变化，再做 3 并发；需要扩展到 5/10 并发时与借票通过率分开报告。

真实阶段若有界预算内拿不到有效路线，只能报告当时未获得正样本；应验证目标持续被拦截、后台正常退避，不能绕过准入完成演示或宣布成功率已提高。

本文件保留设计和自审依据；最终交付状态以实际实现说明与测试结果为准。近期目标是独立管理来源、严格按有效路线放行和完整记录真实结果；长期空窗覆盖、复杂库存优化和未经验证的成功率排序不作为第一版验收目标。
