# 借票业务优先调度与请求生命周期修复（2026-10-11）

## 最终行为

普通 OpenAI HTTP 业务请求先经过原有的分组、模型、权限、健康、冷却和并发规则，再优先选择开启借票且具有可接单路由的账号。借票账号都不可用或没有可立即取得的并发槽时，尝试普通账号；所有账号都忙时保留有界等待。优先调度不会增加账号、用户或 API Key 的并发额度。

同一优先层内使用原有账号调度规则。会话绑定的借票账号满载时，先尝试其余借票账号，避免它的等待计划遮挡空闲容量；尝试数量有上限。普通账号上的会话绑定不会在试选借票账号时被删除或提前改写。只有最终获得槽位的借票账号才提交新的调度绑定，并继续遵守利润门的延迟绑定规则。

账号内继续使用已经实现的最新可接单路由优先。无路由、超过接单截止、旧身份、旧目标版本、撤销或仅验证路由都不能通过路由准入。账号选中后的路由预留仍由数据库事务再次选择，沿用新路由切换时的新会话规则。

原生 previous_response_id 的账号归属、Guardian 任务归属、WebSocket 和媒体请求仍按其原有约束调度；借票 HTTP 续接经已有兼容处理后仍被限定在经过归属验证的目标账号内。

## 修复点

### 客户端结束后借票流仍占用

正常流式转发会分离客户端取消信号，以继续收集上游用量。此前借票路由租约也依附于这个分离后的上下文，客户端结束后仍可能持续续租。

现在在上游上下文分离时保留最初客户端生命周期，并由借票路由使用者监听。客户端取消或超时后，取消借票上游、关闭响应体，随后以独立且有界的清理上下文释放租约。读取退出后原有 handler 释放账号并发槽，认证层结束时释放 Key 槽。正常 EOF、读错误、主动 Close、租约丢失共用只执行一次的收尾。

普通账号保留现有用量收尾语义；借票请求已经收到的用量仍由现有业务记录链路处理。本次没有增加自动重放或重试已开始输出的请求。

### 账号选择之后、首次转发之前路由失效

首次 HTTP 转发准入的 borrow_route_unavailable 现在和账号绑定变化一样，可进入既有的有界重选流程，并保留原始借票错误原因。只有尚未发送、尚未向客户端写入响应、无不允许迁移的会话状态且切换额度未耗尽的请求可以重选。后续发送中的准入错误不会被标成首次发送错误。

HTTP 入口回归模拟：先选中借票账号 11，首次转发准入时使其路由失效，实际只有普通账号 12 收到一次业务请求，最终完成响应。

### 库存与候选是否值得验证使用同一快照

保留现有按库存缺口、续期和维护节奏补充的实现。候选有效期比较改为直接使用库存快照中最早的可用路由期限，去掉另一次范围不一致的数据库查询，避免用已经不满足新请求准入条件的历史路由作为比较基准。

回归验证库存目标为 2 时：已有 1 条路由仍允许取票；补足后停止本批多余取票；Cookie 期限缩短导致一条路由退出可接单库存后重新补充；完成验证的候选直接发布。

### 调度开销与可观测性

业务调度只批量读取开启借票的目标 ID，不读取观察页面的探测计数和扫描历史。实际路由身份、模型和接单期限仍经过原有准入检查。Responses 调度日志增加 borrow_preferred 字段，表示本次是否由借票优先层成功取得账号槽位。
