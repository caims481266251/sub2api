## 目标探测策略与业务隔离（2026-10-10）

在 **借票管理 → 目标账号** 的每个目标卡片，或 **正常账号编辑 → 启用借票** 下，设置并保存：

| 设置 | 默认值 | 范围 | 作用范围 |
| --- | --- | --- | --- |
| 探测并发数 | 2 | 1–32 的整数 | 每个目标账号独立计算 |
| 剩余多少秒恢复探测 | 15 秒 | 0–240 的整数秒 | 每个目标账号独立计算；0 表示到期再探测 |

后台约每秒检查一次：无可用路由时开始获取；最佳可用路由剩余有效期大于提前量时暂停新增探测；小于或等于提前量时恢复探测。期限采用路由与 Cookie 首次观察期限中的较早值，仍遵守后台开关、请求预算及上游明确等待。因此 15 秒是触发阈值，不是保证完成续接的时间。

每个目标并发执行来源取票和目标两阶段验证，单个候选的两阶段仍按顺序执行。来源可用数量、来源独占租约和请求预算仍可能降低实际同时探测数量。两个目标默认各有 2 个探测名额，不再由全局 3 个目标任务上限限制。首个通过的候选发布后取消并清理本轮其余工作。诊断扫描仍逐个来源处理，保证进度准确。

正常业务请求使用**目标账号自身配置的代理**，未配置则直连，不继承路由密文内的代理或旧借票专用目标代理。来源获取 Cookie 使用来源的借票专用代理及固定指纹；目标验证保留目标验证环境。来源取票和目标验证都不占正常账号的业务并发槽，探测连接池、连接数与客户端缓存预算也与业务隔离。目标的每个 HTTP 探测发送前在数据库中预约名额，多实例也不能超过已保存上限。

正常业务请求不写入借票请求表，也不产生业务成功／失败事件；原有业务请求日志继续负责记录。借票记录查询同时过滤旧版本产生的业务事件，保留来源取票、目标验证、候选处置、轮换与路由状态变化。业务发现路由确实失效时，仍撤销该路由并记录路由状态变化。

业务无可用借票路由时，响应尚未开始的请求返回标准 HTTP `429`，`error.type` 为 `rate_limit_error`，供调用方沿用现有 429 换号策略。调度阶段过滤后无可用账号、转发阶段发现路由不可用，均保留此分类；模型不存在等其他错误保持原有分类。本改动不新增换号、重试、等待借票或同步探测，不改变代理、并发和会话逻辑。已开始响应的请求保持原有流内错误处理，不能重新修改 HTTP 状态码。

修改策略采用独立版本号，不修改路由版本或会话绑定。保存并发下调后，不中断在途探测，新请求等待已占名额释放；未保存草稿在刷新、目标页签切换后保留，冲突时需恢复最新配置。进入提前探测窗口、探测失败和发布替代路由都不会提前撤销旧路由；既有会话在旧路由仍有效时继续使用原绑定。

新增迁移 `278_ticket_borrow_probe_policy.sql`，为现有目标填入默认 3 / 15。实现阶段的隔离验收记录见 `.dev/v2.10.1/borrow-probe-policy-20261010/README.md`，包括后端竞态、数据库集成、前端测试、前后端构建及桌面／390px 手机端模拟 API 浏览器验证。部署状态以本文顶部的最新发布记录为准。

## 来源代理与指纹手动、自动切换（2026-10-10 修正）

自动轮换只作用于**来源账号的借票专用环境**。入口是 **智能运维 → 借票管理 → 来源账号**。目标页不提供代理／指纹轮换，目标环境及已发布的有效路由不随来源切换而改变。

来源表支持单行“随机切换代理＋指纹”，也支持勾选后批量切换。单行“自动轮换设置”会定位到来源配置区，可选择来源，设置自动开关和间隔。默认 **60 秒**，允许 **1–86400 整数秒**，保存后生效。刷新、切换来源或页签保留未保存草稿；版本冲突时需先恢复服务端配置。

手动切换与自动轮换统一采用随机重排：所有可用代理平等参与，不再按全局未用、来源未用或最久未用排序。允许复用历史代理，不要求池中存在全新资源。仍排除当前代理、停用／移除代理、批次外账号占用的代理和其他任务预留的代理。没有完整替代分配方案则整个批次保留原绑定。

来源轮换区提供“全部来源一键重排”，无需逐个勾选即可提交所有已有代理绑定的来源。满池可在本批来源之间互换，不会抢占批次外账号的绑定。任一来源的自动计时到期时，会把全部已有绑定且有效的来源纳入同一批次，包括没有单独启用自动计时的来源；与手动批次共用同一分配规则。原有各来源开关、间隔保持，开启的计时在整批结束后重新计算。

代理使用记录和指纹历史继续保存用于追溯。当前 v2 指纹生成优先排除全局历史中的 TLS 握手结构，最多尝试 64 次后按来源／全局使用次数选择合格配置回退；每次重新生成设备 ID。配置与客户端身份完整保存，同一环境的重试和重连复用该快照。页面显示代理分配结果、出口地址和指纹摘要。

任务先预留完整批次并阻止新的来源采集，等待本批来源租约排空，再在同一事务更新代理、设备 ID、环境版本和代理使用记录；单批排空最多 180 秒，超时保留原绑定。来源下一次采集自动使用新环境。账号日常业务代理、OAuth 刷新、请求预算、上游等待，以及目标路由和会话均保持原有约束。

策略、下一次时间和未完成任务持久保存，关闭页面和服务重启不影响配置。自动任务不重叠，不补跑积压轮次；下一轮从本轮完成、失败或取消后计时。后台借票暂停时停止自动触发并取消尚未提交的自动来源任务，手动来源切换仍可操作。暂停时已提交的环境不回滚。来源移出范围、账号失效或预留代理失效时整批取消／失败。

API：`GET/POST /admin/accounts/ticket-borrowing/rotations` 读取状态／提交任务；提交携带 UUID `request_id`、`role: source`、`account_ids`。相同请求 ID 重试不重复切换，`role: target` 明确拒绝。`PUT /admin/accounts/:id/ticket-borrowing/rotation` 为来源保存 `revision`、`automatic`、`interval_seconds`。接口仅管理员可用。

新增迁移 `277_ticket_borrow_source_rotation_history.sql`，保留已有 `276` 不改写：允许来源自动轮换，停用旧目标轮换策略、取消旧未完成计划并释放预留，建立历史表及存量绑定回填。已存在的旧目标环境保留只读兼容，不在升级时改动目标代理或已发布路由。自动轮换默认关闭，不把旧目标的开关直接转给来源。

此修正实现阶段通过 61 项后端竞态测试、35 项集成套件测试、37 项前端测试、类型检查、前后端生产构建及桌面／390px 手机端模拟 API 浏览器验收，当时未部署或启用真实账号请求。代码与隔离验收记录位于 `.dev/v2.10.1/borrow-source-rotation-20261010/`。部署状态以本文顶部的最新发布记录为准；下方较早上线记录属于历史记录。固定的是代理配置与设备/TLS 配置，实际出口 IP 取决于代理供应商。

## 代理池自动绑定与后台自动借票（当前实现）

来源页新增“自动绑定代理池并固定借票指纹”，保存后生效。按所选分组与账号的并集，为正常来源账号自动分配启用代理；代理不足时按绑定数量均匀共享，每个来源保留独立设备指纹；目标账号及影子账号不参与分配。分配保存在 `ticket_borrow_proxy_bindings`，日常业务代理配置不变，OAuth 令牌刷新继续由正常账号的现有刷新流程负责。

- 相同绑定跨采集轮次和服务重启保持代理、设备标识及由设备标识派生的 TLS 配置。池模式强制关闭每轮身份轮换。页面只显示无认证信息的出口地址和指纹摘要。
- 池内代理少于来源账号时允许均匀共享；没有启用且未移除的代理时显示等待并停止采集，不能回退为直连。停用或移除代理后，旧绑定立即不具备发送资格；在途来源租约结束后再自动重新分配。来源移出选择范围会释放绑定，其他来源的绑定保持稳定。
- 每次尝试和传输建连后、写出前检查来源选择、账号资格、代理绑定和设备标识。配置变化会阻止旧环境继续发送。代理凭据只在内部解密，来源列表与事件不返回密码、原始代理 URL 或设备标识。
- 固定的是代理配置和设备/TLS 配置；代理供应商仍可能轮换实际出口 IP。HTTP、HTTPS、SOCKS5H 均沿用显式代理路径；HTTPS 代理先验证代理证书，再建立 CONNECT 隧道，并在隧道内使用目标 TLS 指纹。

后台策略中的“启用后台获取”保存后，后台约每秒检查已启用目标。没有有效路由时自动选择来源、获取 Cookie、完成目标复验，通过后发布路由；有效路由剩余时间大于目标提前量时暂停新增探测，进入提前量窗口后恢复，默认提前 180 秒，并受最低剩余有效期规则约束。来源全局预算与每目标探针预算、明确的上游等待继续独立生效。暂停后台后不再预约新的请求，已发布路由仍按原截止时间有效。运行不依赖管理页面是否打开。

启用步骤：在代理管理中准备启用的代理 → 在借票来源页选来源并开启自动绑定、保存 → 在正常账号编辑中开启目标借票 → 在借票策略中启用后台获取、保存。默认不在数据库升级时替管理员启动真实请求。

新增迁移为 `275_ticket_borrow_proxy_bindings.sql`；已有迁移不改写。新选项默认关闭，旧选择与后台启停状态保持原值。以下较早版本的预热、分阶段恢复和上线记录属于历史说明；当前以每目标提前探测策略、独立请求预算为准。

## 选择来源

1. 在“来源账号”页勾选一个或多个 OpenAI 分组，和/或单独勾选正常 OpenAI OAuth/setup-token 账号。两者取并集，以正常账号 ID 去重。
2. 分组成员变动在下一次来源解析时生效。移出所选分组后，如果账号仍被单独选择，继续保留。页面显示来源是来自分组还是单独指定。
3. 配置默认来源模型（默认 `gpt-6-luna`）。每个账号可以覆盖该模型，留空使用默认；配置仅作用于借票采集，正常账号模型映射依然生效。
4. 保存来源选择。账号禁用、暂停调度、冷却或过期时不能采集；借票目标和影子账号不能作为来源，防止循环借票或重复凭据身份。
5. 在“借票策略”启用后台获取，在“目标账号”查看路由状态，也可请求获取新路由或完整扫描当前来源。

编辑凭据和出口代理请进入“管理正常账号”，不会在借票页面重新导入或保存另一份凭据。来源列表接口只返回元数据；来源引用的数据库行不允许持有凭据密文。正常来源请求使用正常账号资源 ID，使用独立的借票并发和连接池，仍遵守正常令牌刷新协调及上游限制。每次 HTTP 重试及建连后发送前检查来源是否仍被选中、账号是否仍合格、身份/代理是否改变。

“每轮更新设备标识与 TLS 指纹”只影响这次采集请求环境，不修改正常账号配置；不宣称完整浏览器档案、独立出口 IP 或提高上游通过率。代理随正常账号配置读取，正常账号的令牌由既有 TokenProvider 负责刷新。

## 自动补票与请求预算

在“借票策略”启用后台获取后，系统为启用借票的目标获取和提前续接路由。候选寿命上限默认 230 秒，可设 30–240 秒，最终期限受上游 Cookie、首次观察和验证耗时约束。恢复探测提前量默认 180 秒，由借票策略提供全局值，目标账号可单独覆盖。

来源请求预算默认全局每分钟 12 次，目标探测预算默认每个目标每分钟 12 次，均采用滚动 60 秒窗口并在发送前预约。连接失败和重试也计入；正常一个候选验证包含两次目标请求。并发数控制同时探测的数量，请求预算控制发送频率，两者独立。业务请求不计入这些预算。

普通候选失败后继续尝试其他候选，不增加人为固定冷却。HTTP 429 和流内明确限流、额度、认证或权限错误仍触发独立的上游等待，使用既有结构化错误和 Retry-After 规则。手动获取、诊断扫描和策略修改不能清除上游等待；业务结束也不延长探测等待。

暂停后台会阻止新增获取与探测，已发送工作按有界租约清理。有效路由继续服务，目标页在途数仅统计探测。完整扫描用于逐个诊断来源；有可用路由且尚未到提前探测阈值时同样暂停，达到阈值后继续未完成进度。

此前版本的真实验证属于历史记录，见 [借票恢复与真实回归](ticket-borrowing-recovery-20261010.md)。本轮仅使用模拟上游和隔离数据库验证，不以此推断真实上游通过率。

## 借票日志保留

借票记录默认保留滚动最近 **24 小时**，按记录的 `created_at` 与数据库时间计算，不按自然日切分，也不限制一天内的记录条数。来源获取、目标探测、路由及代理轮换事件共用这一规则。

升级时清理现有超期事件；服务启动后每分钟检查并删除超期记录，后台借票暂停或轮换处理失败时仍执行。清理失败会短暂等待后重试。日志接口直接排除超过 24 小时的事件，页面中已加载的历史也随时间过期。

此规则仅作用于 `ticket_borrow_events`，正常业务使用记录、计费记录、测试请求/SSE/答案文件，以及代理和指纹使用历史不受影响。请求诊断、轮换任务等其他表维持原清理策略。

## 目标准入

目标仍在正常账号编辑里开启“启用借票”。当前资格范围为 `gpt-6-astra` / HTTP Responses。其他模型、WS/Live 或没有有效路由时拒绝调用。请求使用目标自身的认证材料，不转发来源 OAuth。

资格使用 `now < expires_at`；剩余 15 秒、1 秒或不足一秒都允许新请求。连接/DNS/TLS等待结束后、实际写出前再次检查。到期后阻止新请求，已经开始的响应流不因到期而中断。

更改来源选择、移出分组、停用来源、后台失败或暂停、路由替换和服务重启都不提前撤销已发布的有效路由。原会话继续绑定原路由至原截止时间；不能把过期续接静默切到新路由。明确的认证拒绝、新门票/路由变更只撤销相关绑定；网络超时不会自动重放业务。

## 旧独立来源迁回

数据库迁移 `270_ticket_borrow_normal_sources.sql` 只更新结构，不自动移动凭据。管理员在借票策略暂停后台获取，等待所有在途来源和目标租约结束后，点击来源页“迁回正常账号”。

迁回为单个事务：恢复原正常账号 ID、原分组及历史；凭据维护权交还正常账号，清除来源引用行内密文；旧单个借票代理移到正常代理管理并绑定原账号；原来源模型作为账号级覆盖保留，并自动加入“单独选择账号”。恢复正常调度开关，账号原状态、冷却和有效期限制仍保留。

原来源 ID、路由、会话、测试记录、迁移记录均保留；借票事件额外返回正常来源账号 ID。重复迁回不重复创建代理或账号。事务要求后台已暂停且无活动租约；迟到的旧来源刷新不能把凭据写回引用行。旧的独立来源创建、编辑、删除和转出 API 返回 410，引导使用正常账号管理。

当前兼容迁回支持曾从正常账号转出的来源、且每来源至多一个专用代理。有多个代理或没有原账号映射的旧来源会保留数据，需要先明确正常账号归属/代理配置；不会静默丢弃额外代理或猜测账号。

## 存储与测试

- `ticket_borrow_selection` 保存分组/账号并集、默认模型、账号覆盖及 CAS revision。
- `ticket_borrow_sources.account_id` 只引用正常账号，保留借票租约和历史 ID。分组解析每次读取当前数据库，普通账号中编辑代理/凭据后无需复制到借票库。
- PostgreSQL 保持路由、截止时间和租约的唯一权威。每目标一个任务租约和独立探测并发上限（默认 2）；来源独占租约防止同一来源重叠采集，探测不占业务并发槽。
- 目标原有有效路由不依赖当前来源是否仍被选中。
- 本次新增回归覆盖动态分组成员、重叠选择去重、模型覆盖、目标排除、探测与业务并发隔离、正常凭据/模型映射、迁回幂等与凭据所有权、代理迁回、历史 ID 与截止时间保持。

本次改造不等同于上游借票成功率提升。此前真实边界与性能问题见 `ticket-borrowing-live-review-20261010.md`；该报告中的业务并发互相阻塞已由本轮隔离处理，真实上游表现仍需另行观察。

## 来源配置操作与界面状态

借票管理顶部按“选择来源 → 配置自动获取 → 查看目标路由”提供入口；概览使用已保存配置与后台状态。来源表单依次选择范围、设置默认模型与身份轮换、核对来源明细，底部操作栏保存整份来源配置。

- 分组和单独账号仍取并集。选择器标记“已由所选分组包含”，搜索结果可批量单选或取消单选；取消单选不会排除仍属于所选分组的账号。无法找到的已选 ID 可以逐项移除。
- 来源明细每页 10 个，可搜索及筛选暂不参与、单独指定模型的候选。基本条件符合数量仅检查目标身份、账号状态与调度开关，不保证一定可采集；实际还受模型、额度、冷却、代理、并发等条件约束。
- 默认模型只影响“跟随默认”的账号。现有迁回账号保留单独模型配置，页面会显示覆盖数量；可以逐个或批量恢复跟随默认，保存后生效。列表中的最近结果属于已保存配置，不能作为未保存草稿可用性的证明。
- 来源和策略各自维护草稿与版本。刷新、切换页签、保存另一份表单不会覆盖草稿。离开页面有未保存提示；“恢复服务端配置”明确丢弃该表单的草稿。发现服务端版本变化时不自动变更草稿版本或重试覆盖，需要恢复最新配置后重新编辑。
- 后台暂停时，目标的获取与扫描入口禁用，提供前往策略的入口；已有扫描仍可停止后续任务。已保存的后台状态与策略开关草稿分离。暂停不改变有效路由的实际到期时间。
- “路由可用”表示满足借票路由条件，普通账号/分组/额度限制仍然适用。后台阶段、最近结果与当前网关分开显示，来源取得 Cookie 不等于目标验证通过。扫描进度包含跳过来源，并不保证每个来源完成目标复验。
- 候选寿命可设置 30–240 秒，默认 230 秒；上游 Cookie 有效期与验证耗时会影响最终可用时间。补票阈值不会提前禁用现有有效路由。
- 目标与来源运行状态每 5 秒刷新；事件通过“刷新”加载最新页，通过“加载更早记录”回溯并去重。阶段使用中文名称，原始结果代码可展开查看。

### 候选观测详情

`2.10.1-borrow-observation-1` 起，新事件可展开候选详情，查看来源模型、gateway、复验准备时和记录时的票龄/剩余寿命、来源尝试数、目标阶段状态及环境摘要。来源、目标复验、未使用候选通过候选 ID/批次关联；通过事件记录发布路由 ID；普通业务请求记录在独立业务日志中。预取后未验证的候选显示独立原因，不作为目标失败统计。

环境摘要反映请求构造和代理配置，不等于实际出口 IP 或完整浏览器指纹。历史事件没有该详情。不会显示原始 Cookie、票据、认证、代理密码和业务正文。页面“路由可用”表示满足当前协议验证与期限条件，不代表所有业务题目一定回答正确。

`2.10.1-borrow-prefetch-1` 起，普通模式成功发布路由后会取消本批尚未完成的来源采集，并等待清理释放资源。此类来源显示“采集已取消”，不计作来源网络失败；已完成但未使用的候选仍有独立记录。完整扫描不会因某个来源通过而提前结束，已发布路由仍按自身期限服务。

`2.10.1-borrow-stop-1` 将相同的清理顺序覆盖到检测到暂停、冷却、认证/限流和其他终止条件之后。失败候选触发冷却时立即结束该批，不再等另一个来源返回后才检查冷却。先取消采集，再等待清理并释放任务；完整扫描只推进已处理的来源，仍有效的业务路由不受影响。该改动减少无效等待和槽位占用，不改变上游复验判据或冷却时长。

`2.10.1-borrow-signal-1` 补齐来源和目标 HTTP 200 流内限流／额度／认证信号，详见 [流内失败审查与验证](ticket-borrowing-stream-signal-20261010.md)。这是重试与等待修复，不能单独证明上游路由接受率提高。
