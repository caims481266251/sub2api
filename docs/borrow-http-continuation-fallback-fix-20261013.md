# 借票 HTTP 续接同组兜底修复

日期：2026-10-13。范围：Responses HTTP 借票续接的发送前换号。

## 问题与行为

生产分析确认，携带 `previous_response_id` 的借票续接被限制为原 TargetID；原目标准入失败时，即使同组正常帐号健康，也无法进入候选列表。

修复后，原目标可用时保持原有处理。原目标出现借票准入失败时，若本轮确定尚未发送、上下文完整且可迁移，就在当前请求内转换一次，排除原目标，并交给现有同组调度器。其他借票帐号和正常 API-key 帐号继续遵守原有优先级、模型、分组、健康、并发和 RPM 规则。立即可用的候选在原目标的短时路由等待之前参与选择，整个请求共用原来的等待对象与预算。

数据库层将响应绑定缺失标记为 `ErrBorrowContinuationBindingMissing`，将无合格路由标记为 `ErrBorrowNoEligibleRoute`；两者仍兼容 `errors.Is(ErrBorrowUnavailable)`。调度器保留实际 cause，真实存储错误不获得跨帐号迁移资格。

## 完整上下文如何证明

HTTP 原先只保存响应归属和路由，没有完整历史。此次实现增加有界的摘要证据，而不保存、自动补齐或猜测历史：

1. 服务端观察经过认证的请求输入和成功完成响应，计算规范化内容的 SHA-256 链式摘要及条目数。
2. 后续请求必须携带完整历史，其前缀必须与该响应已有证据一致；用户、API Key、分组和原处理帐号也必须一致。
3. 仅规范化语义等价的消息形式和无语义的输出 id/status 等字段；工具调用的 call_id、name、arguments 仍参与校验。
4. 工具输出必须有实际配对调用；conversation、item_reference、加密内容、帐号所属文件/向量库/显式容器引用不参与迁移。
5. 证据只在本进程内存中有效，最多 8,192 条，最长 30 分钟（不超过响应归属 TTL）；输入/输出各限 4 MiB，总条目最多 4,096。内存中长期保留的只有摘要、条目数、归属 ID 和过期时间。

**适用边界：** 重启前的旧响应、到其他实例的请求、证据过期/被淘汰、只有增量输入或包含不可迁移状态的请求，仍保持原帐号约束。它们在原帐号可用时照常处理；原帐号不可用时返回明确的续接错误。本修复没有实现 HTTP 历史恢复，也不保证所有既有 503 都能透明恢复。客户端可以携带完整上下文、不传 previous_response_id，作为新请求进入正常同组选号。

## 状态与发送边界

迁移使用请求副本清除旧目标、response/session 绑定，生成一次新的会话身份，清除头及 client_metadata 中的旧 turn-state/turn-metadata。Body、GetBody 和 ContentLength 保持一致。原始业务输入继续供审核和计费使用；旧响应的全局归属不删除，其他并发请求不受影响。

借票恢复对象仅解除原目标约束，保留等待截止时间、尝试次数、取消状态和发送证据。选号后的路由失效必须带有原有的首次发送前拒绝证明。已进入真实传输、可能写入、已输出、取消、任务所有权绑定或换号预算耗尽时，不新增迁移权限。帐号槽位和路由租约沿用既有释放流程；RPM 沿用现有严格计数策略，不重置已消耗次数或把旧预留转给新帐号。

新响应沿用原有归属写入逻辑，绑定实际承接帐号。真实上游 429、5xx 和连接错误继续使用既有策略。

## 错误与日志

- 成功兜底：正常业务响应。
- 可用候选耗尽：使用现有选号错误分类，容量不足为 503；模型配置和 RPM 分类保持原逻辑。
- 原续接不可用且无法安全迁移：503 / api_error，稳定 code 为 `borrow_continuation_unavailable`。
- 存储/控制面失败：保留具体内部 cause，返回准入不可用错误。
- 原有输入和归属校验失败：继续使用原协议。

新增结构化日志 `openai.borrow_http_continuation_fallback`、`openai.borrow_http_continuation_fallback_refused`、`openai.borrow_http_continuation_outcome`，记录请求关联、原/最终帐号、准入子原因、迁移拒绝原因、换号次数及最终状态。响应 ID 仅记录摘要。
